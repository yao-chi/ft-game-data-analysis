# 金铲铲之战 · 自走棋运营策略数据分析

> 一个"对抗模拟 → 回合级数据 → 运营策略归因"的完整数据分析项目，
> 覆盖 **经济系统 / 流派比较 / 比赛进程 / 血量与连胜管理** 四个运营命题。

## 项目亮点

- **自研数据管线**：金币经济引擎 → 四流派策略模拟 → 战力-胜负结算 → 回合级明细（21.6 万行）→ 玩家级聚合 → 9 张图表 + 结构化结论；
- **零第三方依赖作图**：图表全部用自研 SVG 渲染器绘制（bar / line / multi-line / heatmap），**不依赖 matplotlib / seaborn**，单文件 HTML 报告离线可看；
- **seed=42 完全可复现**：一条命令重跑全流程，数据、图表、结论逐位一致；
- **结论可直接落地**：6 条发现均从数据中生成，指向可操作的运营建议（流派选择、利息与存钱的量级、连胜滚雪球、血量运营窗口）。

## 数据怎么来的（诚实说明）

金铲铲之战官方不开放对局级数据。本项目基于**公开可查的游戏机制认知**构造模拟样本：

- 收入 = 基础 5 + 利息（存款每 10 金 +1，封顶 5）+ 连胜/连败奖励（封顶 4）；
- 四种运营流派（存钱 / 速本 / 赌狗 / 均衡）各有存款目标与花费偏好参数；
- 人口升级费用、战力构成、对战扣血按游戏常识建模，胜负由阵容强度差 + 噪声决定；
- 固定随机种子，结论可复现。

**项目价值在方法而非数据来源**：完整演示了"问题 → 指标设计 → 数据构造 → 清洗聚合 → 多维分析 → 可落地结论"的数据科学工作流，这正是数据科学岗位考察的核心能力。

## FAQ

**为什么不用 matplotlib？**
让报告"零安装即可复现"——自研 SVG 渲染器保证任何机器上 `python` 一条命令跑完，产物是纯 HTML/SVG，无环境依赖，也展示了图表系统的实现功底。

**为什么选金铲铲之战？**
自走棋的"排名制 + 回合制经济"与 MOBA 的"胜负制"数据形态完全不同：名次是多元目标（前四吃分）、经济是持续决策流（存利息 vs 抽卡 vs 升人口）、血量是硬约束。分析这样的数据需要不同的指标与因果视角，能体现对游戏品类的迁移理解。
